# CONTRACT.md — Interface contract for the Cloud Suite project

> Internal engineering contract. **Every teammate must read this file before writing.**
> It is the single source of truth for service names, ports, networks, env-var names,
> file paths, and ownership of write scopes. Do not change anything here without the Lead.

## 1. Product

Self-hosted S3-based replacement for Yandex.Disk for an organisation:

| Requirement (from the customer) | Implemented by |
|---|---|
| S3 object storage instead of Yandex.Disk | SeaweedFS S3 gateway (`s3`) as **primary object store** of Nextcloud |
| Web GUI | Nextcloud (`app` + `cron` + `web`) |
| Nginx-based authorisation / entry point with GUI | Nginx Proxy Manager (`proxy`, GUI on 81) + hardened nginx `web` tier |
| Sharing folders between authorised employees | Nextcloud native shares + groups, policies in `config/rbac/` |
| Public read **and** edit links | Nextcloud link shares with permissions + password + expiry (scripted in `scripts/`) |
| Configurable role model | Nextcloud groups + delegated group admins, declarative `config/rbac/roles.yaml` |
| Audit logging of user actions | `admin_audit` app → JSON-lines audit log + nginx JSON access logs |
| Versioning up to 20 versions (configurable) | `files_versions` + count-based pruner (`VERSIONS_MAX`) |
| Built-in office | ONLYOFFICE Docs 8.3.3 in Docker, JWT protected |
| Production readiness | healthchecks, pinned images, backups/restore, DR docs, CI validation |

**Hard constraint:** everything is deployed by `docker compose` on a single Linux VM
(Ubuntu 24.04 LTS / Debian 12) with a public IP and DNS names. No Kubernetes.

### 3.1 Local run overlay (`docker-compose.local.yml`)

Optional overlay for a single-machine run **without a domain, DNS or TLS**
(`docs/13-local-run.md`). It is a separate compose project
(`COMPOSE_PROJECT_NAME=cloudsuite-local`) with its own volumes, so it never
touches the production stack.

| Service | Override | Effect |
|---|---|---|
| `proxy` | `profiles: ["edge"]` | NPM does not start (no domains/TLS/ACME) |
| `web` | `ports: 127.0.0.1:${LOCAL_HTTP_PORT:-8080}:8080`, `ipv4_address: ${LOCAL_WEB_IP:-172.28.10.11}`, `CLOUD_DOMAIN=${LOCAL_HOST:-cloud.local}` | Nextcloud on loopback at `http://cloud.local:8080` |
| `app`, `cron` | `OVERWRITEPROTOCOL=http`, `OVERWRITEHOST=${LOCAL_HOST}:${LOCAL_HTTP_PORT}`, `OVERWRITECLIURL`, local trusted domains | correct absolute URLs without TLS |
| `onlyoffice` | `ports: 127.0.0.1:${LOCAL_OFFICE_PORT:-8081}:80` | editor reachable from the browser |

Invariants: every published port is bound to `127.0.0.1`; `PROXY_IP` in
`.env.local` equals `LOCAL_WEB_IP`, so `extra_hosts` maps the local host name to
the `web` container and server-side ONLYOFFICE callbacks resolve. Base
`docker-compose.yml` stays unchanged: the overlay only adds keys, it never uses
`!reset` or `!override` (the validator and PyYAML cannot parse those tags).

Local host names MUST NOT be in the `*.localhost` zone: browsers, glibc and
musl (and `curl` itself) force that zone to loopback and ignore `/etc/hosts`,
so ONLYOFFICE could not reach Nextcloud by the callback URL (verified live: DS
resolved `cloud.localhost` to `127.0.0.1` and every callback failed with
"Connection refused"). The overlay therefore uses `cloud.local`/`office.local`;
the workstation maps them to `127.0.0.1` once via `scripts/local-hosts.sh`
(`make local-hosts`), while containers get the same names through
`extra_hosts`. `scripts/local-hosts.sh` refuses `*.localhost` on purpose.

### 3.2 White-IP overlay (`docker-compose.ip.yml`)

Optional overlay for a server with a **public IPv4 and no domain**
(`docs/14-ip-run.md`). Separate compose project
(`COMPOSE_PROJECT_NAME=cloudsuite-ip`) with its own volumes.

| Service | Override | Effect |
|---|---|---|
| `proxy` | `profiles: ["edge"]` | NPM does not start (no domain, no ACME/TLS) |
| `web` | `ports: ${IP_BIND:-0.0.0.0}:${IP_HTTP_PORT:-80}:8080`, `ipv4_address: ${IP_WEB_IP:-172.28.10.12}`, `CLOUD_DOMAIN=${PUBLIC_IP}` | Nextcloud at `http://PUBLIC_IP/` |
| `app`, `cron` | `OVERWRITEPROTOCOL=http`, `OVERWRITEHOST=${PUBLIC_HOST}`, `OVERWRITECLIURL=http://${PUBLIC_HOST}`, trusted domains include `PUBLIC_IP` | correct absolute URLs without TLS |
| `onlyoffice` | `ports: ${IP_BIND:-0.0.0.0}:${IP_OFFICE_PORT:-8081}:80` | editor reachable from the browser at `http://PUBLIC_IP:8081/` |

Invariants:

- `PUBLIC_HOST` is `PUBLIC_IP`, or `PUBLIC_IP:IP_HTTP_PORT` when the port is not 80;
  it must match `PUBLIC_BASE_URL` (the image regenerates `reverse-proxy.config.php`
  from `OVERWRITEHOST` on every start, so a mismatch makes `make ip-configure` fail);
- `PUBLIC_IP` must be globally routable — `make ip-env` rejects loopback/private ranges;
- `CLOUD_DOMAIN` is the public IP, `OFFICE_DOMAIN` is a **distinct** service alias
  (`office.internal`): compose rejects duplicate `extra_hosts` entries
  (`extra_hosts must be a mapping`) when both are the same string;
- `PROXY_IP` equals `IP_WEB_IP` (172.28.10.12, distinct from the prod .10 and local .11);
- ONLYOFFICE callback URLs contain the bare public IP, which a container cannot
  always reach (provider 1:1 NAT, no NAT loopback). `scripts/ip-callback-route.sh`
  therefore adds ONE idempotent DNAT rule in the onlyoffice network namespace
  (`PUBLIC_IP:IP_HTTP_PORT -> IP_WEB_IP:8080`, needs `NET_ADMIN` for a throw-away
  container only). Nothing on the host and no host iptables rule changes;
- the run is plain HTTP (no certificate for a bare IP): TLS requires a domain
  (production profile) or an external TLS proxy;
- base `docker-compose.yml` stays unchanged (no `!reset`/`!override`; PyYAML-safe).

## 4. Environment variable contract (`.env`)

Names are **exactly** as below; defaults live in `.env.example`. Compose must fail fast
(`${VAR:?message}`) for secrets.

```
COMPOSE_PROJECT_NAME, TZ
CLOUD_DOMAIN, OFFICE_DOMAIN, ACME_EMAIL, HTTP_PORT, HTTPS_PORT,
NPM_ADMIN_BIND, NPM_ADMIN_PORT, NPM_ADMIN_EMAIL, NPM_ADMIN_PASSWORD
NEXTCLOUD_ADMIN_USER, NEXTCLOUD_ADMIN_PASSWORD, NEXTCLOUD_VERSION,
PHP_MEMORY_LIMIT, PHP_UPLOAD_LIMIT, NEXTCLOUD_TRUSTED_DOMAINS,
POSTGRES_DB, POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_VERSION,
REDIS_PASSWORD, REDIS_VERSION,
S3_BUCKET, S3_REGION, S3_ACCESS_KEY, S3_SECRET_KEY, S3_USE_PATH_STYLE,
SEAWEEDFS_VERSION, SEAWEEDFS_VOLUME_SIZE_MB, SEAWEEDFS_FILER_PORT, SEAWEEDFS_S3_PORT,
NPM_VERSION, MAIL_DOMAIN,
ONLYOFFICE_JWT_SECRET, ONLYOFFICE_JWT_HEADER, ONLYOFFICE_JWT_IN_BODY, ONLYOFFICE_VERSION,
VERSIONS_MAX, VERSIONS_RETENTION_DAYS, TRASH_RETENTION_DAYS,
BACKUP_RETENTION_DAYS, BACKUP_DIR, BACKUP_PASSPHRASE,
SMTP_HOST, SMTP_PORT, SMTP_SECURE, SMTP_USER, SMTP_PASSWORD, SMTP_FROM,
NGINX_VERSION, CRON_INTERVAL_SECONDS, LOG_LEVEL, TRUSTED_PROXIES, PROXY_IP
```

Rules:
- `TRUSTED_PROXIES=172.28.10.0/24` and `PROXY_IP=172.28.10.10`.
- `PHP_UPLOAD_LIMIT` (e.g. `10G`) is propagated to nginx `client_max_body_size` and PHP.
- `NEXTCLOUD_TRUSTED_DOMAINS` = `${CLOUD_DOMAIN} ${OFFICE_DOMAIN} web`.
- Nextcloud S3 env vars are the image-native `OBJECTSTORE_S3_*` set (mapped from `S3_*`).
  The TLS switch MUST be passed as `OBJECTSTORE_S3_SSL=false`: the image's `s3.config.php`
  reads `OBJECTSTORE_S3_SSL` (an `OBJECTSTORE_S3_USE_SSL` variable is silently ignored and
  S3 access breaks with TLS against a plain-HTTP SeaweedFS gateway — verified live).
- `NPM_ADMIN_EMAIL`/`NPM_ADMIN_PASSWORD` are seeded into Nginx Proxy Manager as
  `INITIAL_ADMIN_EMAIL`/`INITIAL_ADMIN_PASSWORD` (first boot, empty DB), so the GUI login is
  deterministic instead of the legacy `admin@example.com/changeme` + setup wizard.
- OnlyOffice must run with `ALLOW_PRIVATE_IP_ADDRESS: "true"` because `extra_hosts` resolves
  the public cloud domain to the private `172.28.10.10`; otherwise the editor opens but the
  document never downloads (DS blocks private IPs by default — verified).
- `HTTP_PORT`/`HTTPS_PORT` must be free on the host; if another stack owns :80 the NPM
  container starts but never answers HTTP (verified: a foreign Apache answered instead).
- Never commit `.env`; only `.env.example` (with empty secrets) is tracked.
- `scripts/generate-secrets.sh` fills every empty secret with a strong random value.

Local run (.env.local, template in `.env.local.example`): the same keys plus
`COMPOSE_PROJECT_NAME=cloudsuite-local`, `LOCAL_HOST`, `LOCAL_OFFICE_HOST`,
`LOCAL_HTTP_PORT`, `LOCAL_OFFICE_PORT`, `LOCAL_WEB_IP`, `PUBLIC_BASE_URL`,
`DOCUMENT_SERVER_URL`. Rules:

- `PUBLIC_BASE_URL` drives `overwriteprotocol`/`overwritehost`/`overwrite.cli.url`
  in `configure-nextcloud.sh` (default when unset: `https://${CLOUD_DOMAIN}`).
- `DOCUMENT_SERVER_URL` is the browser URL of the editor (default:
  `https://${OFFICE_DOMAIN}/`).
- `PROXY_IP` MUST equal `LOCAL_WEB_IP` (= `web` static IP), otherwise ONLYOFFICE
  callbacks point to the wrong container.
- Host names MUST NOT end in `.localhost` (see §3.1).
- `.env.local` is gitignored; `.env.local.example` is tracked with empty secrets.

White-IP run (`.env.ip`, template in `.env.ip.example`): `COMPOSE_PROJECT_NAME=cloudsuite-ip`,
`PUBLIC_IP`, `PUBLIC_HOST`, `IP_BIND`, `IP_HTTP_PORT`, `IP_OFFICE_PORT`, `IP_WEB_IP`,
`PUBLIC_BASE_URL`, `DOCUMENT_SERVER_URL`, plus the production secrets. Rules:

- `PUBLIC_IP` is the public IPv4 of the server; `make ip-env` validates it and
  refuses loopback/private ranges.
- `PUBLIC_HOST` = `PUBLIC_IP`, or `PUBLIC_IP:IP_HTTP_PORT` when the port is not 80;
  `PUBLIC_BASE_URL` must be `http://${PUBLIC_HOST}` (compared by
  `configure-nextcloud.sh` against the image-generated `reverse-proxy.config.php`).
- `DOCUMENT_SERVER_URL` is the browser URL of the editor: `http://PUBLIC_IP:IP_OFFICE_PORT/`.
- `OFFICE_DOMAIN` is a distinct service alias, never equal to `CLOUD_DOMAIN`.
- `PROXY_IP` MUST equal `IP_WEB_IP` (172.28.10.12).
- `.env.ip` is gitignored; `.env.ip.example` is tracked with empty secrets.

## 5. Routing contract (what NPM must be configured with)

| Hostname | Upstream (docker DNS) | TLS | Extra |
|---|---|---|---|
| `$CLOUD_DOMAIN` | `http://web:8080` | Let's Encrypt + Force SSL + HSTS | websocket upgrade, `client_max_body_size $PHP_UPLOAD_LIMIT`, long timeouts |
| `$OFFICE_DOMAIN` | `http://onlyoffice:80` | Let's Encrypt + Force SSL + HSTS | websocket upgrade for co-editing, big buffers, 3600s timeouts |
| SeaweedFS admin (:9333 master, :8888 filer) | not routed by default | — | admin-only opt-in via `docker-compose.admin.yml` |

`proxy` is pinned to `172.28.10.10`; `app`, `cron` and `onlyoffice` get
`extra_hosts: ["${CLOUD_DOMAIN}:172.28.10.10", "${OFFICE_DOMAIN}:172.28.10.10"]`
so server-side callbacks never hairpin through public DNS.

| Host path | Container path | Service | Mode |
|---|---|---|---|
| `config/nginx/nginx.conf` | `/etc/nginx/nginx.conf` | web | ro |
| `config/nginx/conf.d/` | `/etc/nginx/conf.d` | web | ro |
| `config/nginx/snippets/` | `/etc/nginx/snippets` | web | ro |
| `logs/nginx/` | `/var/log/nginx` | web | rw |
| `config/nextcloud/php.ini` | `/usr/local/etc/php/conf.d/zz-cloudsuite.ini` | app, cron | ro |
| `config/nextcloud/` (весь каталог) | `/opt/cloudsuite` | app, cron | ro |
| `config/nextcloud/hooks/` | `/docker-entrypoint-hooks.d` | app, cron | ro |
| `config/redis/redis.conf` | `/usr/local/etc/redis/redis.conf` | cache | ro |
| `logs/cloudsuite/` | `/var/log/cloudsuite` | app, cron | rw (uid 33) |
| `logs/nginx/` | `/var/log/nginx` | web | rw (uid 101) |
| onlyoffice_data / onlyoffice_lib / onlyoffice_logs (named) | /var/www/onlyoffice/Data, /var/lib/onlyoffice, /var/log/onlyoffice | onlyoffice | rw |

NOTE: OnlyOffice `local.json` is generated by the image at first start and **must not** be
bind-mounted; JWT settings come from env (`JWT_ENABLED`, `JWT_SECRET`, `JWT_HEADER`, `JWT_IN_BODY`).

`web` mounts `nextcloud_html` **read-only** at `/var/www/html` for static assets and
`/var/www/html/data` is denied by nginx config (never served).

Nextcloud config files are **not** bind-mounted into `/var/www/html/config`: a file mount there
makes Docker create the `config` directory as root before the image starts, which breaks the
first-boot install ("Не удаётся записать в каталог «config»" — verified live). Instead the whole
`config/nextcloud` tree is mounted at `/opt/cloudsuite` and the entrypoint hooks apply it:

- `10-extra-config.sh` — copies `/opt/cloudsuite/config/*.config.php` into `/var/www/html/config`
  on every start (repository is the source of truth);
- `20-permissions.sh` — makes `/var/www/html/config` writable by www-data (uid 33);
- `30-enable-audit.sh` — idempotently enables the `admin_audit` app (disabled by default in NC 35).

Hooks run as **www-data** (the image's `run_as`), must keep the executable bit and must never
abort the container on error. Scripts run `/opt/cloudsuite/custom/prune-versions.php` inside `app`.

SeaweedFS `-s3.config` is **not** used (4.x ignores it in `weed server`): `s3-init` applies the
S3 identity with `weed shell s3.configure ... -apply` (idempotent) and creates the bucket;
so there is no `config/seaweedfs/s3.json` and nothing to generate at bootstrap.

Audit log path: `/var/log/cloudsuite/audit.log` (system config `logfile_audit`), app log
`/var/log/cloudsuite/nextcloud.log` (`logfile`); host side: `./logs/cloudsuite/`, owner uid 33.

## 8. Naming / style rules

- docker compose file format: no obsolete `version:` key; anchors for logging/security.
- All containers: `restart: unless-stopped`, `TZ`, `logging` limits,
  `security_opt: [no-new-privileges:true]`, `stop_grace_period`.
- Nginx: HTTP/2, TLS 1.2+1.3 (in NPM), security headers, no `server_tokens`,
  immutable caching for static, JSON access log to `/var/log/nginx/access.json.log`.
- Scripts: `#!/usr/bin/env bash`, `set -Eeuo pipefail`, `--help`, `--dry-run` where
  destructive, idempotent, use `.env` via `scripts/lib/common.sh`, shellcheck-clean.
- Python validation: stdlib + PyYAML only, exit non-zero on any failure, `make test`.
- Docs: Russian (customer language), markdown, code blocks with exact commands,
  cross-links valid, no placeholder like "TODO" or "yourdomain.com" in final docs
  (use `cloud.example.com` consistently and `.env` values).

    `files_sharing.outgoing_server2server_share_enabled`/`incoming_...` = no.
12. `occ_set_system redis host cache` трактует третий аргумент как --type: вложенные
    redis.* пишутся только как `config:system:set redis <key>` (`occ_set_system_nested`).
13. `grep -q` в конце конвейера при `set -o pipefail` даёт ложные "not enabled":
    grep закрывает пайп, писатель получает SIGPIPE (`app_enabled` сравнивает строки).
14. `extra_hosts` с двумя одинаковыми пунктами Compose v5 отвергает с невнятным
    "extra_hosts must be a mapping" -> в режиме белого IP `CLOUD_DOMAIN` (это IP) и
    `OFFICE_DOMAIN` обязаны различаться (служебное `office.internal`).
15. Образ Nextcloud на каждом старте пересобирает `reverse-proxy.config.php` из
    env `OVERWRITEHOST`, поэтому порт в `PUBLIC_HOST` и `PUBLIC_BASE_URL` должен
    совпадать, иначе `configure` падает на проверке overwritehost.
16. NAT loopback на публичный IP из контейнера не работает (в живом прогоне
    `curl http://203.0.113.10:18080/status.php` из onlyoffice — таймаут 8 с):
    callback'и ONLYOFFICE ломаются даже при верных URL -> правило DNAT внутри
    netns onlyoffice (`scripts/ip-callback-route.sh`, нужен только `NET_ADMIN`).
