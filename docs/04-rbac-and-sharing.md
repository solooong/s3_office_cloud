# 04. Ролевая модель и совместная работа

Ролевая модель задаётся декларативно в `config/rbac/roles.yaml` — это
единственный источник правды. Скрипт `scripts/rbac-sync.sh` (цель `make rbac`)
приводит Nextcloud к состоянию файла: создаёт группы, применяет квоты, назначает
делегированных администраторов, выставляет политики шаринга.

## 1. Принципы

1. **Группа — единица прав.** Пользователь не получает права напрямую: он входит
   в группу, группа описана в `roles.yaml`.
2. **Default deny.** Всё, что не разрешено явно, запрещено: нет публичных ссылок у
   аудиторов, нет решаринга у подрядчиков, нет федеративных шаров.
3. **Наименьшие привилегии.** Администратор — не участник общих папок; руководитель
   отдела управляет только своим отделом (групп-админ).
4. **Повторяемость.** Изменения ролей вносятся только правкой YAML + `make rbac`,
   а не «руками в интерфейсе», иначе состояние невоспроизводимо.
5. **Смена роли — не переименование группы.** Переименование создаёт новую группу и
   теряет связи с общими папками.

## 2. Роли, квоты и политики

Значения ниже — фактические из `config/rbac/roles.yaml` (версия 1).

| Роль (группа) | Отображаемое имя | Квота | Назначение |
|---|---|---|---|
| `admins` | Администраторы | `unlimited` | полное администрирование, в общие папки по умолчанию не входит |
| `management` | Руководители подразделений | `500GB` | делегированные администраторы своих групп, отчёты, состав |
| `employees` | Сотрудники | `100GB` | базовая роль: личное пространство, общие папки отдела, публичные ссылки |
| `contractors` | Внешние подрядчики | `20GB` | только выданные папки, короткие ссылки без права редактирования |
| `auditors` | Аудиторы / ИБ | `5GB` | чтение выделенных папок, без публичных ссылок и редактирования |

Политика шаринга по ролям (поля `share.*`):

| Роль | Ссылки разрешены | Пароль обязателен | Срок по умолчанию | Публичное редактирование | Решаринг | Федеративные шары |
|---|---|---|---|---|---|---|
| `admins` | да | да | 30 дней | да | да | нет |
| `management` | да | да | 30 дней | да | да | нет |
| `employees` | да | да | 30 дней | да | да | нет |
| `contractors` | да | да | 7 дней | **нет** | **нет** | нет |
| `auditors` | **нет** | — | — | **нет** | **нет** | нет |

Политики по умолчанию (`defaults`): квота без роли — `10GB`, пароль на
ссылке обязателен, срок 30 дней, публичное редактирование разрешено, решаринг
разрешён, федеративные шары выключены.

## 3. Структура roles.yaml

```yaml
version: 1

defaults:
  default_quota: "10GB"
  enforce_link_password: true
  link_expire_days: 30
  allow_public_edit: true
  resharing: true
  remote_shares: false

roles:
  - name: employees              # идентификатор группы в Nextcloud
    display_name: "Сотрудники"   # отображается в UI
    description: "..."           # для администраторов
    quota: "100GB"               # 0/unlimited = без ограничения
    delegated_admins: []         # логины, кто становится group admin
    share:
      links_allowed: true
      enforce_password: true
      default_expire_days: 30
      public_edit_allowed: true
      resharing: true
      remote_shares: false
```

Правила заполнения:

* `name` — латиница, цифры, `-`, `_`, `.`, `@`; менять нельзя без миграции;
* `quota` — строка в формате Nextcloud (`5GB`, `500GB`, `unlimited`);
* `delegated_admins` — логины существующих пользователей; каждый получает
  права администратора указанной группы (не глобального администратора);
* `share.`* — применяется через настройки шаринга Nextcloud и проверяется в
  `--dry-run` (расхождения печатаются как `DIFF`).

## 4. Применение ролей

```bash
# посмотреть, что изменится (ничего не меняет)
make rbac DRY_RUN=1
# или напрямую
./scripts/rbac-sync.sh --dry-run

# применить
make rbac

# отчёт о результате
./scripts/rbac-sync.sh --dry-run --json | jq .
```

Скрипт идемпотентен: повторный запуск не меняет состояние и завершается успешно.
Что он делает:

1. создаёт отсутствующие группы, обновляет отображаемые имена;
2. выставляет квоты ролям и пользователям без явной роли (`defaults.default_quota`);
3. назначает/снимает делегированных администраторов групп;
4. применяет политики шаринга (пароль, срок, редактирование, решаринг,
   федеративные шары);
5. печатает сводку: создано / изменено / без изменений.

Проверка результата:

```bash
docker compose exec -T -u www-data app php occ group:list
docker compose exec -T -u www-data app php occ user:info ivanov | grep -E 'quota|groups'
docker compose exec -T -u www-data app php occ config:app:get core shareapi_enforce_links_password
```

## 5. Матрица прав

Обозначения: **Д** — доступ есть, **Н** — нет, **Р** — только чтение,
**Ч/З** — чтение и запись.

| Действие | admins | management | employees | contractors | auditors |
|---|---|---|---|---|---|
| Вход в веб-интерфейс | Д | Д | Д | Д | Д |
| Личное пространство (свои файлы) | Д | Д | Д | Д | Д |
| Создание общих папок отдела | Д | Д | по согласованию | Н | Н |
| Просмотр общих папок отдела | Д | Д | Д | только выданные | Р |
| Загрузка/изменение файлов | Д | Д | Ч/З | Ч/З в выданных | Р |
| Удаление файлов | Д | Д | Ч/З | Н | Н |
| Внутренний шаринг | Д | Д | Д | только внутри выданных | Н |
| Публичная ссылка «чтение» | Д | Д | Д | Д | Н |
| Публичная ссылка «редактирование» | Д | Д | Д | Н | Н |
| Решаринг | Д | Д | Д | Н | Н |
| Управление пользователями группы | Д | Д (своя группа) | Н | Н | Н |
| Просмотр отчётов по квотам | Д | Д | Н | Н | Д |
| Просмотр аудит-логов | Д | Н | Н | Н | Д |
| Изменение системных настроек | Д | Н | Н | Н | Н |

Матрица — целевое состояние; расхождения с UI означают, что `make rbac` не
выполнялся или настройки правились вручную.

## 6. Внутренние общие папки

Соглашение об именах (важно для прав и бэкапов):

```text
/Общие/Отдел ИТ/            -> группа employees + management (ИТ)
/Общие/Бухгалтерия/         -> группа buh (или employees, если отдел один)
/Общие/Проект <название>/   -> конкретные сотрудники + подрядчики (гости)
/Личное/<логин>/            -> только владелец
```

Правила:

* общие папки создаёт владелец отдела и шарит **на группу**, а не на список
  фамилий — иначе новые сотрудники не получат доступ;
* права по умолчанию: «Редактирование» без «Поделиться» (решаринг — по матрице);
* удаление чужого файла из общей папки попадает в корзину владельца папки;
* переименование общей папки — только через владельца, иначе ломаются ярлыки
  синхронизации.

Как расшарить (UI): «Файлы» → «…» у папки → **«Поделиться»** → ввести группу →
права → **«Отправить»**.

## 7. Публичные ссылки

### 7.1 Политика

| Параметр | Значение по умолчанию | Кто может изменить |
|---|---|---|
| Пароль | обязателен для всех ролей | ИБ через `roles.yaml` |
| Срок действия | 30 дней (сотрудники), 7 дней (подрядчики) | роль |
| Право редактирования | разрешено сотрудникам, запрещено подрядчикам/аудиторам | роль |
| Просмотр списка ссылок | владелец файла + администратор | — |
| Отзыв всех ссылок пользователя | администратор при увольнении | — |

### 7.2 Создание через UI

«Поделиться» → **«Поделиться ссылкой»** → **«+»** → выбрать права → задать пароль →
задать дату → скопировать ссылку. Пароль передаётся получателю **отдельным
каналом**.

### 7.3 Создание через OCS API

```bash
# read-only ссылка на файл: permissions=1 (read)
curl -sS -u ivanov:"$APP_PASSWORD" \
  -H 'OCS-APIRequest: true' \
  -X POST 'https://cloud.example.com/ocs/v2.php/apps/files_sharing/api/v1/shares' \
  --data-urlencode 'path=/Документы/договор.pdf' \
  --data-urlencode 'shareType=3' \
  --data-urlencode 'permissions=1' \
  --data-urlencode 'password=СложныйПароль123' \
  --data-urlencode 'expireDate=2026-12-31' \
  | jq '.ocs.data | {url, permissions, expiration}'

# редактируемая ссылка на папку: permissions=15 (read+update+create+delete)
curl -sS -u ivanov:"$APP_PASSWORD" \
  -H 'OCS-APIRequest: true' \
  -X POST 'https://cloud.example.com/ocs/v2.php/apps/files_sharing/api/v1/shares' \
  --data-urlencode 'path=/Общие/Проект Альфа' \
  --data-urlencode 'shareType=3' \
  --data-urlencode 'permissions=15' \
  --data-urlencode 'password=СложныйПароль123' \
  --data-urlencode 'expireDate=2026-11-30'
```

`APP_PASSWORD` — пароль приложения (создаётся в настройках пользователя), не
основной пароль. Список ссылок: `GET .../shares?shared_with_me=false`, удаление:
`DELETE .../shares/<id>`.

Биты прав OCS: 1 — чтение, 2 — обновление, 4 — создание, 8 — удаление,
16 — решаринг. Для файла «редактирование» = 3, для папки — 15 (без решаринга) или
31 (со решарингом, запрещён политикой).

### 7.4 Что видит гость

Только содержимое выданного узла. Прямой переход по URL к родительским каталогам
возвращает 404: ссылка не является «точкой входа» в дерево. Имена других файлов
пользователя не раскрываются.

## 8. Внешние пользователи (гости)

В текущей поставке отдельное приложение «Guests» не используется: внешний
подрядчик — это учётная запись с ролью `contractors`.

Порядок выдачи:

```bash
# 1) создать пользователя (пароль сгенерировать, передать отдельным каналом)
docker compose exec -T -u www-data app php occ user:add --password-from-env \
  --display-name "Пётр Сидоров (подрядчик)" contractor_petrov
# 2) добавить в группу contractors (квота и политики применятся через make rbac)
docker compose exec -T -u www-data app php occ group:adduser contractors contractor_petrov
# 3) выдать доступ к конкретной папке
docker compose exec -T -u www-data app php occ sharing:share \
  "/Общие/Проект Альфа" contractor_petrov 1
```

Особенности:

* срок доступа подрядчика фиксируется в договоре; по окончании —
  `occ user:disable contractor_petrov`;
* подрядчик не может создавать публичные ссылки с редактированием и решарить;
* доступ ко всему дереву «Общие» не выдаётся: только к проектной папке.

## 9. Делегированное администрирование (руководитель отдела)

Руководитель отдела — участник `management` и администратор своей группы:

```bash
# назначить sub-admin группы
docker compose exec -T -u www-data app php occ group:add-subadmin employees petrova

# проверить
docker compose exec -T -u www-data app php occ group:list --info
```

В `roles.yaml` это фиксируется в `delegated_admins`:

```yaml
  - name: management
    delegated_admins: [petrova, sokolov]
```

Руководитель может: добавлять/удалять участников группы, видеть квоты, управлять
общими папками отдела. Не может: менять системные настройки, видеть аудит-логи
других отделов, назначать глобальных администраторов.

## 10. Onboarding и offboarding

### 10.1 Новый сотрудник

```bash
# 1) учётная запись (пароль сгенерирован и передан лично/через СМС)
docker compose exec -T -u www-data app php occ user:add --password-from-env \
  --display-name "Иван Иванов" ivanov

# 2) роль
docker compose exec -T -u www-data app php occ group:adduser employees ivanov

# 3) применить квоты/политики (если менялись)
make rbac

# 4) при необходимости — доступ к общим папкам отдела
docker compose exec -T -u www-data app php occ sharing:share \
  "/Общие/Отдел ИТ" ivanov 3
```

Чек-лист: учётная запись создана, роль назначена, квота верна, вход выполнен,
2FA включена, клиент установлен, инструкция [10-user-guide.md](10-user-guide.md)
отправлена, сотрудник добавлен в группу отдела.

### 10.2 Увольнение / уход подрядчика

```bash
# 1) заблокировать вход
docker compose exec -T -u www-data app php occ user:disable ivanov

# 2) отозвать все сессии и пароли приложений
docker compose exec -T -u www-data app php occ user:auth-tokens:delete --all ivanov

# 3) передать файлы руководителю отдела
docker compose exec -T -u www-data app php occ files:transfer-ownership \
  ivanov petrova

# 4) удалить из групп (кроме не-удаляемых)
docker compose exec -T -u www-data app php occ group:removeuser employees ivanov

# 5) проверить, что публичные ссылки пользователя больше не работают
./scripts/rbac-sync.sh --dry-run --json | jq '.users[]? | select(.user=="ivanov")'
```

Важно: `user:disable` блокирует вход, но **не** отключает ранее созданные
публичные ссылки автоматически. Ссылки удаляются администратором
(`DELETE /ocs/v2.php/apps/files_sharing/api/v1/shares/<id>`) или скриптом
инвентаризации ссылок. После увольнения в течение 24 часов проверьте
`logs/cloudsuite/audit.log` на активность учётной записи.

## 11. Изменение ролей и аудит

* любое изменение `roles.yaml` — через pull request и `make rbac` (не
  правкой UI);
* каждое применение фиксируется в `logs/cloudsuite/audit.log` как действие
  администратора (записи `User "<логин>" added to group "<группа>"`);
* при спорных ситуациях поднимается история: кто и когда добавил пользователя в
  группу:

  ```bash
  jq -r 'select(.message | test("added to group|removed from group"))
    | [.time, .user, .message] | @tsv' logs/cloudsuite/audit.log | tail -n 50
  ```

## 12. Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| Сотрудник не видит общую папку | папка расшарена на фамилию, а не на группу | перешарить на группу |
| Квота не применилась | не запускался `make rbac` или квота задана пользователю вручную | `make rbac`, проверить `occ user:info` |
| Пароль на ссылке не требуется | политика не применена | `make rbac`, проверить `shareapi_enforce_links_password` |
| Подрядчик может редактировать по ссылке | роль не та / ссылка выдана до смены роли | сменить группу, пересоздать ссылку |
| Руководитель видит чужие группы | назначен глобальным админом | снять админку, оставить sub-admin |
| После переименования группы пропали общие папки | переименование = новая группа | восстановить старое имя, мигрировать шары |
