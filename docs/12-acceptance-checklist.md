# 12. Чек-лист приёмки в эксплуатацию

Документ используется при сдаче контура заказчику и при повторной приёмке после
крупных изменений (обновление major-версии, смена хранилища, переезд). Каждый пункт
имеет ожидаемый результат; пункт считается принятым только при его совпадении.
Отклонения фиксируются в листе замечаний с указанием серьёзности.

## 1. Как проводить приёмку

| Параметр | Значение |
|---|---|
| Участники | ИТ-администратор (исполнитель), представитель заказчика (приёмка), ИБ (раздел безопасности) |
| Длительность | 4–6 часов, отдельное окно, не в часы пик |
| Данные | тестовая организация: 3 группы, 6 пользователей, 1 гость |
| Инструменты | браузер (Chrome/Firefox), desktop-клиент, `curl`, `jq`, `occ`, сканер портов (с внешнего хоста) |
| Фиксация | протокол с ID тестов, фактическим результатом, скриншотами ключевых шагов |

Перед началом: `make doctor` и `make status` должны быть зелёными.

## 2. Предусловия

- [ ] ВМ соответствует требованиям ([01-architecture.md](01-architecture.md#11-требования-к-ресурсам)).
- [ ] DNS: `$CLOUD_DOMAIN` и `$OFFICE_DOMAIN` резолвятся в публичный IP.
- [ ] `make bootstrap` выполнен, `.env` заполнен, секреты сгенерированы.
- [ ] `docker compose ps`: все сервисы `healthy` (или `running` для one-shot
      `s3-init`, который завершился с кодом 0).
- [ ] Сертификаты Let's Encrypt выпущены для обоих доменов.
- [ ] `make configure` выполнен (Nextcloud настроен, коннектор OnlyOffice активен).

## 8. Критерии подписания

Приёмка считается успешной, если:

* все пункты разделов 3–7 пройдены (или отклонения согласованы письменно с
  указанием срока устранения);
* критичных (S-01, S-05, S-08, S-09, S-12, B-01, B-05) и высоких отклонений нет;
* бэкап и восстановление выполнены **фактически**, а не «по инструкции»;
* подписаны: протокол приёмки, акт ввода в эксплуатацию, регламент резервного
  копирования, матрица ролей.

## 9.1 Результаты прогона на живом стенде

Ниже — фактически подтверждённые результаты эталонного развёртывания
(Nextcloud 35.0.2.2, SeaweedFS, ONLYOFFICE 8.3.3, PostgreSQL 17, Redis 8.4.7).
Их можно использовать как ожидаемые значения при приёмке.

| Область | Проверено | Результат |
|---|---|---|
| Установка | первый старт `make up` | Nextcloud 35.0.2.2 установлен автоматически, `installed: true` |
| S3 primary storage | WebDAV `PUT` / `PROPFIND` / скачивание | `PUT` 201, `PROPFIND` 200, объект `urn:oid:11` в бакете `nextcloud`, round-trip совпал |
| Публичная ссылка | OCS create + анонимное скачивание | create 200 с токеном, `GET /s/<token>/download` → 303 на `https://cloud.example.com/...` |
| Аудит | `logs/cloudsuite/audit.log` | JSON-строки: включение приложения, консольные команды, `The shared file with the token ... has been accessed`; `admin_audit` включается хуком `30-enable-audit.sh` |
| Версии | `oc_files_versions` + прунер | 2 версии; `prune-versions --max=1` удалил одну, повторный dry-run — 0 удалений; `versions_retention_obligation=auto, 30` |
| Кэш | `memcache.local` / `distributed` / `locking` | APCu / Redis / Redis; логи в `/var/log/cloudsuite/nextcloud.log` |
| edge-nginx | `status.php`, `/.well-known/caldav`, deny-листы, `TRACE`, неизвестный Host | 200 / 301 (относительный Location) / 404 / 405 / 444 |
| Redis | старт с `config/redis/redis.conf` | `rename-command CONFIG` намеренно отсутствует (Redis 8.4.7 падает при старте), `FLUSHALL`/`FLUSHDB`/`SHUTDOWN` переименованы, `maxmemory 1gb`, `noeviction` |
| compose | рендер четырёх комбинаций (base/admin/observability) | `docker compose config -q` — успех, 9 базовых сервисов |
| Валидация репозитория | `make test` | `tests/validate.py`: 199 проверок, 0 ошибок, 2 предупреждения; compose-рендер `9 passed` |
| Линтеры | `make lint` | shellcheck 0.11.0: 0 замечаний на 16 скриптах, `bash -n` чисто |
