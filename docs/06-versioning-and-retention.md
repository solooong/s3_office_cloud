# 06. Версии файлов и политика хранения

## 1. Зачем нужны версии

Сотрудники работают с документами напрямую в браузере и через клиенты
синхронизации, часто без промежуточных копий. `files_versions` сохраняет
предыдущее состояние файла перед перезаписью, поэтому случайная правка, неудачное
сохранение из OnlyOffice или ошибочная синхронизация не уничтожают данные
безвозвратно. Требование заказчика — до 20 версий на файл с возможностью
настройки.

## 2. Как устроены версии при S3-primary

В Nextcloud версия — это отдельный файл в служебном каталоге `files_versions`
хранилища пользователя. При S3-primary хранилище физически находится в бакете
`S3_BUCKET`:

```text
S3 bucket nextcloud
├── urn:oid:1001           <- текущая версия документа
├── urn:oid:1002           <- версия 1
├── urn:oid:1003           <- версия 2
└── ...
```

* метаданные версий (какому файлу принадлежат, время, размер) лежат в PostgreSQL
  (`filecache`, `files_versions`);
* на диске ВМ версий нет — они не занимают место в docker-томе `nextcloud_data`,
  а расходуют квоту пользователя в S3;
* версия создаётся при перезаписи существующего файла, при загрузке новой версии
  через WebDAV/клиент и при сохранении из ONLYOFFICE;
* переименование и перемещение файла версии не теряет;
* удаление файла отправляет его в корзину; версии удаляются вместе с ним после
  очистки корзины (п. 5).

Практическое следствие: восстановление версии — это операция с объектами S3 через
PHP; она не требует доступа к снапшотам диска, но **требует** живую БД. Поэтому
бэкап без дампа PostgreSQL версии не восстановит.

## 3. Две независимые политики

| Политика | Кто управляет | Параметр | Что делает |
|---|---|---|---|
| Временная (native) | приложение `files_versions` | `VERSIONS_RETENTION_DAYS` → `versions_retention_obligation` | удаляет версии старше N дней |
| Количественная (pruner) | `scripts/prune-versions.sh` | `VERSIONS_MAX` | оставляет не более N версий на файл |

Обе включены одновременно: временная защищает от «вечного» роста, количественная
обеспечивает требование «20 версий». Отключение одной из них не является
поддерживаемой конфигурацией.

### 3.1 Временная политика

В `config/nextcloud/config/zz-10-cloudsuite.config.php` задаётся

```php
'versions_retention_obligation' => 'auto, ' . VERSIONS_RETENTION_DAYS,
```

то есть при `VERSIONS_RETENTION_DAYS=30` действует `'auto, 30'`: Nextcloud сам
создаёт и группирует версии, а версии старше 30 дней удаляет. Формат значения:

| Значение | Смысл |
|---|---|
| `auto` | приложение само решает, когда создавать версии и когда чистить |
| `'auto, N'` | автосоздание + удаление версий старше N дней (используется) |
| `'D1, D2'` | гарантированно хранить D1 дней, удалять после D2 (ручной режим) |
| `D, auto` | хранить D дней, дальше — по усмотрению приложения |

Проверить действующее значение:

```bash
./scripts/occ.sh config:system:get versions_retention_obligation
```

Изменение — через `.env` (`VERSIONS_RETENTION_DAYS`) и перезапуск `app` и `cron`,
либо разово:

```bash
./scripts/occ.sh config:system:set versions_retention_obligation --value='auto, 30'
```

Важно: `occ config:system:set` пишет в `config.php` внутри тома
`nextcloud_html`; при пересоздании тома значение потеряется. Постоянные настройки
хранятся в `config/nextcloud/config/zz-10-cloudsuite.config.php` (монтируется
read-only), а `occ` используется для проверки и разовых изменений.

### 3.2 Количественная политика (VERSIONS_MAX)

Реализация — PHP-скрипт `config/nextcloud/custom/prune-versions.php`, единственная и
версионируемая копия. Каталог `config/nextcloud` монтируется в контейнеры `app` и
`cron` как `/opt/cloudsuite:ro`, поэтому в контейнере прунер доступен по пути
`/opt/cloudsuite/custom/prune-versions.php`. Копировать PHP в том `nextcloud_html`
не нужно. Обёртка `scripts/prune-versions.sh` проверяет окружение и
запускает скрипт от имени `www-data`:

```bash
# что будет удалено (ничего не меняет)
make prune-versions-dry-run
# или напрямую
./scripts/prune-versions.sh --dry-run

# применить (обычно по расписанию)
make prune-versions

# напрямую в контейнере (то же, что делает обёртка)
docker compose exec -T -u www-data app php /opt/cloudsuite/custom/prune-versions.php --max=20 --dry-run

# временно изменить лимит для одного прогона
./scripts/prune-versions.sh --max 10

# только JSON-сводка, без построчного вывода
./scripts/prune-versions.sh --quiet
```

Алгоритм:

1. по таблице `oc_files_versions` находится файлы, у которых версий больше N;
2. для каждого файла через публичный API `files_versions` (`IVersionManager`)
   запрашивается список версий и сортируется по времени (новые первыми);
3. всё, что старше N-й версии, удаляется через `IDeletableVersionBackend` —
   это корректно удаляет и объект в S3, и записи в БД;
4. в конце печатается JSON-сводка.

Прунер **не** удаляет файлы и не правит `filecache` вручную — метаданные
остаются согласованными, что критично для S3-хранилища.

Флаги обёртки:

| Флаг | Значение |
|---|---|
| `--max N` | переопределить `VERSIONS_MAX` для этого прогона (целое ≥ 1) |
| `--quiet` | не печатать каждую удаляемую версию, только JSON |
| `-n`, `--dry-run` | показать, ничего не удаляя |
| `-h`, `--help` | справка |

Флаги PHP-скрипта (передаются обёрткой): `--max=N`, `--quiet`, `--dry-run`.

Сводка содержит `max_versions`, `files_scanned`, `files_pruned`,
`versions_deleted`, `errors` и `dry_run`:

```bash
./scripts/prune-versions.sh --quiet | jq '{max_versions, files_scanned, files_pruned, versions_deleted, errors}'
```

Коды возврата: `0` — успех, `1` — часть удалений не удалась (смотрите
`errors`), `2` — ошибка окружения (нет контейнера, неверный `VERSIONS_MAX`).
Для cron важен код 1: он означает, что часть версий осталась сверх лимита.

### 3.3 Расписание

Прунер запускается по cron хоста, а не через Nextcloud cron: это тяжёлая операция,
которую нельзя растягивать на 300-секундный интервал фоновых задач. Запуск
ежечасный, с `flock` против наложения прогонов:

```bash
# /etc/cron.d/cloudsuite-versions
17 * * * * root cd /opt/cloudsuite && flock -n /var/lock/cloudsuite-prune.lock make prune-versions >> /var/log/cloudsuite/prune.log 2>&1
```

Логи прунера — `logs/cloudsuite/prune.log`; ротация — `config/logrotate/cloudsuite`
(копится 12 недельных архивов). Первый прогон всегда `--dry-run`: убедитесь, что `files_scanned` и
`files_pruned` соответствуют ожиданиям. Для больших инсталляций (сотни тысяч
файлов) запускайте полный проход ночью, а не каждый час, и следите за длительностью
по логу.

Проверка, что задание работает:

```bash
tail -n 20 /var/log/cloudsuite/prune.log
grep -c '"errors":0' /var/log/cloudsuite/prune.log
```

## 4. Что видит пользователь

* панель **«Версии»** в сведениях о файле показывает список: дата, размер, кнопки
  «Скачать» и «Восстановить»;
* количество записей ограничено `VERSIONS_MAX`; более старые удаляются прунером;
* версия создаётся не на каждое сохранение: Nextcloud группирует частые изменения.
  При интенсивной работе в OnlyOffice (автосохранение) версии появляются по
  внутренней политике приложения;
* версии занимают квоту пользователя.

## 5. Корзина

| Параметр | Значение | Переменная |
|---|---|---|
| Хранение удалённых файлов | 30 дней | `TRASH_RETENTION_DAYS` |
| Кто очищает | cron Nextcloud (каждые `CRON_INTERVAL_SECONDS`) | — |
| Восстановление | «Удалённые файлы» → «Восстановить» | — |
| Влияние на квоту | удалённые файлы занимают место | — |

Политика задаётся в том же конфиге: `'trashbin_retention_obligation' => 'auto, 30'`.

Команды администратора:

```bash
# размер корзины пользователя
./scripts/occ.sh trashbin:size ivanov

# очистить корзину пользователя (необратимо)
./scripts/occ.sh trashbin:cleanup ivanov

# очистить корзины всех пользователей по политике (используется cron)
./scripts/occ.sh trashbin:expire
```

Версии удалённого файла удаляются вместе с ним после очистки корзины. Если файл
восстановлен, его версии также восстанавливаются.

## 6. Опционально: версионирование бакета S3

SeaweedFS поддерживает версионирование объектов и lifecycle-правила, но для
задачи «20 версий пользователя» оно **не нужно и не используется**: пользовательские
версии — это отдельные объекты `files_versions`, а не ревизии одного ключа.

Включать версионирование бакета имеет смысл только как дополнительную защиту от
ransomware или ошибочного удаления на уровне хранилища:

```bash
# пример для AWS S3 / Ceph RGW (aws-cli, если gateway поддерживает API)
aws --endpoint-url "$S3_ENDPOINT" s3api put-bucket-versioning \
  --bucket "$S3_BUCKET" --versioning-configuration Status=Enabled

aws --endpoint-url "$S3_ENDPOINT" s3api put-bucket-lifecycle-configuration \
  --bucket "$S3_BUCKET" --lifecycle-configuration file://lifecycle.json
```

```json
{
  "Rules": [
    {
      "ID": "expire-old-object-revisions",
      "Status": "Enabled",
      "Filter": { "Prefix": "" },
      "NoncurrentVersionExpiration": { "NoncurrentDays": 30 }
    },
    {
      "ID": "abort-incomplete-multipart",
      "Status": "Enabled",
      "Filter": { "Prefix": "" },
      "AbortIncompleteMultipartUpload": { "DaysAfterInitiation": 7 }
    }
  ]
}
```

Предупреждения:

* версионирование бакета увеличивает объём хранения (каждая перезапись — новая
  ревизия) и не освобождается при удалении файла в Nextcloud;
* `NoncurrentVersionExpiration` должен быть не меньше срока, за который вы
  гарантируете восстановление;
* SeaweedFS поддерживает версионирование не во всех конфигурациях — проверьте на
  тестовом контуре и не включайте «на всякий случай» в продакшене без расчёта диска.

Обычная резервная копия (снапшот тома S3) — более простой и предсказуемый способ
защиты; см. [07-backup-restore-dr.md](07-backup-restore-dr.md).

## 7. Восстановление версии

### 7.1 Через интерфейс

1. «Файлы» → «…» у файла → **«Сведения»** → вкладка **«Версии»**.
2. Выберите версию: дата/время и размер.
3. **«Восстановить»** — версия становится текущей; текущее содержимое сохраняется
   как ещё одна версия (ничего не теряется).
4. **«Скачать»** — забрать копию, не меняя файл.

### 7.2 Через WebDAV

Версии доступны как отдельная коллекция:

```bash
# список версий файла (нужен пароль приложения)
curl -sS -u ivanov:"$APP_PASSWORD" -X PROPFIND \
  -H 'Depth: 1' -H 'Content-Type: application/xml' \
  --data '<?xml version="1.0"?><d:propfind xmlns:d="DAV:"><d:prop><d:getcontentlength/><d:getlastmodified/></d:prop></d:propfind>' \
  'https://cloud.example.com/remote.php/dav/versions/ivanov/versions/12345/' | head -40

# скачать конкретную версию (timestamp — из предыдущего ответа)
curl -sS -u ivanov:"$APP_PASSWORD" -o restored.bin \
  'https://cloud.example.com/remote.php/dav/versions/ivanov/versions/12345/1735689600'
```

### 7.3 Если версия нужна, а файл удалён

1. восстановите файл из корзины;
2. затем восстановите версию по п. 7.1.

Если корзина уже очищена — версии недоступны, остаётся только восстановление из
бэкапа ([07-backup-restore-dr.md](07-backup-restore-dr.md)).

## 8. Расчёт ёмкости

Каждая версия — полноценный объект в S3 (Nextcloud не хранит дельты). Формула:

```text
объём_версий ≈ Σ по файлам (средний_размер × среднее_число_версий)
```

Практическая оценка:

| Сценарий | Активные данные | Доля изменяемых в месяц | Среднее число версий | Доп. объём |
|---|---|---|---|---|
| офисные документы | 1 ТБ | 30 % | 6 | ~1,8 ТБ |
| проектные файлы (CAD/видео) | 1 ТБ | 10 % | 3 | ~0,3 ТБ |
| смешанная нагрузка | 2 ТБ | 15 % | 4 | ~1,2 ТБ |

Отсюда правило: планируйте 1,5–2,5× от объёма активных данных при
`VERSIONS_MAX=20` и активном редактировании. Точный расход смотрите по тому
`s3_data` и по квотам пользователей.

Снизить расход можно: уменьшив `VERSIONS_MAX` (например, до 10), сократив
`VERSIONS_RETENTION_DAYS` или `TRASH_RETENTION_DAYS`. Все три параметра — в
`.env` и применяются при следующем прогоне прунера или перезапуске `cron`.

## 9. Политика конфликтов

* **Одновременное редактирование в браузере** — конфликта нет: OnlyOffice
  использует модель совместного редактирования с блокировками на уровне сессии.
* **Два клиента синхронизации изменили файл** — Nextcloud создаёт конфликтную
  копию `<имя> (conflicted copy ГГГГ-ММ-ДД).docx`; обе версии сохраняются,
  ничего не теряется. Конфликтные копии не удаляются автоматически — их нужно
  разобрать вручную.
* **Файл открыт в OnlyOffice и одновременно перезаписан через WebDAV** — после
  закрытия редактор сохранит свою версию, возникнет версия-конфликт; правильный
  путь — не редактировать файл параллельно вне офиса.
* **Восстановление версии во время редактирования** — не поддерживается: сначала
  закройте документ у всех соавторов.

## 10. Чек-лист эксплуатации версий

- [ ] `VERSIONS_MAX=20` (или согласованное значение) в `.env`.
- [ ] `versions_retention_obligation` задан в `config/nextcloud/config/`.
- [ ] Прунер доступен в контейнере: `docker compose exec -T app test -r /opt/cloudsuite/custom/prune-versions.php`.
- [ ] Cron-задание прунера установлено и логируется.
- [ ] Первый прогон выполнен с `--dry-run`, затем реальный.
- [ ] Отчёт прунера не содержит ошибок (`errors` = 0).
- [ ] Восстановление версии проверено вручную (тест F-35 в
      [12-acceptance-checklist.md](12-acceptance-checklist.md)).
- [ ] Место в S3 под версии учтено в расчёте ёмкости.
